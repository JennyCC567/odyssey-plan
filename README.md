# 人生罗盘 Pathfinder

一个课程项目 demo：从八字命理轻分析进入自我探索，用人生红点十二问作为主线，最终生成三版五年奥德赛计划。

## 产品流程

1. **轻命理开场**
   - 用户输入出生时间、性别、出生城市。
   - 系统调用本地八字排盘脚本，生成四柱、五行分布、日主和轻量画像。
   - 这一层只负责制造兴趣和提供自我观察线索，不替用户下结论。

2. **红点十二问**
   - 以飞书文档中的人生红点十二问为主线。
   - 前 9 问只让用户回答具体事件、画面、情绪和取舍；不展示红点类型名，也不让用户手动选择证据标签。
   - 第 10-12 问才解释红九模型，让用户基于前面的证据参与排除、底线设置和强制排序。
   - 红点诊断草案主要来自用户回答文本、后台线索提取、文本关键词和后期模型确认。

3. **三问一镜像**
   - 每完成 3 问，系统用命理线索做一次“镜像回应”。
   - 镜像回应只帮助用户坚持回答、看见惯性，不参与红点评分。

4. **诊断草案与修订窗口**
   - 系统先生成 Top 3 红点诊断草案，并展示关键证据。
   - 如果证据不足、Top 候选分差过小，或第三/第四候选边界不清，系统显示“不确定，需要补问”，最多补问 2 题，先补充真实取舍案例，不强行进入计划。
   - 2 题后仍不收敛时，进入低置信诊断草案，由用户修订并形成共同结论。
   - 用户可以修订最终 Top 3，形成“专业分析 + 用户认同”的共同共识。

5. **奥德赛计划**
   - 根据共识 Top 3 红点和用户想探索的职业/人生方向，生成三版五年计划：
     - 当前轨道
     - 备用轨道
     - 理想轨道
   - 每版包含五年时间线、四维仪表盘、风险排查、原型实验和第一年路径卡。

## 本地运行

```bash
npm install
npm run setup:python
npm run dev
```

打开：

```text
http://localhost:3000
```

当前环境已创建 `.venv` 并安装 `pytz`、`ephem`，可直接运行开发服务。

## 重要产品原则

- 命理是“兴趣入口”，不是“命运判断”。
- 红点判断必须以已发生的生活证据和用户理解后的确认为主。
- 前期避免让用户凭类型名字或证据标签自我认领，防止误解和自我投射。
- 证据不收敛时必须补问；补问最多 2 题，之后输出低置信草案，不为了流程顺滑强行生成确定结论。
- AI 教练应避免使用“你命中注定”“你一定适合”这类定论式表达。
- 诊断报告是可讨论草案，不是单向判决。
- 奥德赛计划不是唯一答案，而是多个可被低成本测试的人生版本。
